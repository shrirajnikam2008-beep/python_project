WAYPOINT FRONTEND MANUAL PART 2: NEXT.JS 14 APP ROUTER ARCHITECTURE

02 Next.js Architecture Explained

Waypoint is built with Next.js 14 using the App Router paradigm. Rather than configuring complex routing files like in standard React (React Router), Next.js maps the folder hierarchy inside frontend/app/ directly to URL routes.

Core App Router Conventions in Waypoint

  • layout.tsx: The root wrapper. Runs on initial load to set up <html>, <body>, mounts global CSS, and wraps everything in <AuthProvider>. It persists state across page changes without re-mounting.
  • page.tsx: Represents the publicly accessible leaf component for that URL segment.
  • loading.tsx: Built on React <Suspense>. Next.js automatically shows this centered spinner while data is resolving during route transitions.
  • error.tsx: Global client-side error boundary (must declare 'use client'). Catches unhandled runtime exceptions in child components and renders a friendly retry screen without crashing the whole tab.
  • not-found.tsx: Default 404 handler rendered when an invalid URL is requested.

Server vs. Client Components ('use client')

By default, every component in Next.js 14 is a Server Component. Server Components execute solely on the server, generating zero JavaScript in the client's browser bundle.

However, whenever a component needs:

  1. Browser APIs (e.g., localStorage, window, document)
  2. React State or Lifecycle hooks (useState, useEffect, useCallback)
  3. User interactivity (e.g., onClick, onChange, onSubmit)
  4. Third-party canvas manipulation (e.g., React Flow)

It must declare 'use client' at the very top of the file. In Waypoint, interactive viewports (like Dashboard, Onboarding, and Opportunities) are Client Components.

Special Architectural Pattern: RouteMapClient.tsx

React Flow relies heavily on browser DOM measurement (calculating bounding boxes for SVG bezier curves). During Next.js server-side pre-rendering, Node.js has no DOM, which causes hydration mismatches or server crashes.

Waypoint elegantly solves this in frontend/app/route/[id]/RouteMapClient.tsx:

import dynamic from 'next/dynamic'
import { SkeletonCard } from '@/components/ui/SkeletonLoader'

export const RouteMap = dynamic(
  () => import('@/components/route-map/RouteMap').then((m) => m.RouteMap),
  {
    ssr: false, // Disables server pre-rendering for the canvas!
    loading: () => <div className="h-full flex items-center justify-center"><SkeletonCard /></div>,
  }
)

WAYPOINT FRONTEND MANUAL PART 3: USER JOURNEY WALKTHROUGH

03 Trace the Application From Start to Finish

To understand how data flows across the system, let us trace the complete journey of a new student using Waypoint from initial visit to opportunity application.

Step 1: User Opens Website & Views Landing Page

  • Files: frontend/app/layout.tsx → frontend/app/page.tsx → HeroSection.tsx
  • Component: LandingPage(), HeroSection(), HeroRouteViz()
  • State: Framer Motion entrance animation states (opacity: 0, y: 24 → opacity: 1, y: 0).
  • Data: Static SVG visual graph showing nodes (You, Python, Linear Algebra, Data Structures, Machine Learning).
  • API Call: None. Static marketing presentation. Clicking "Start Your Journey" routes to /onboarding.

Step 2: User Signs Up / Authenticates

  • Files: frontend/app/signup/page.tsx → frontend/contexts/AuthContext.tsx
  • Function: handleSignup(e: React.FormEvent) invokes signup() from useAuth().
  • API Invocation: authSignup(name, email, password) in frontend/lib/api.ts.
  • SIMULATED IN BROWSER STORAGE: Validates email uniqueness, creates an account object, encodes credentials via btoa, writes to localStorage.setItem('waypoint_accounts', ...) and localStorage.setItem('waypoint_session', ...), then pushes router to /onboarding.

Step 3: User Completes 4-Step Onboarding

  • File: frontend/app/onboarding/page.tsx
  • Component: OnboardingPage() with sub-components:
    1. ProfileStep.tsx: Captures name, program (e.g., B.Tech IT), and semester.
    2. AcademicStep.tsx: Captures cgpa (e.g., 8.2) and creditsCompleted (60). Computes dynamic standing badge.
    3. SkillsStep.tsx: Multi-select pill cloud toggling acquired skills into currentSkills array.
    4. DestinationStep.tsx: Calls getDestinations() and renders selectable DestinationCard components.
  • Final Submission: Calls createStudentProfile(finalProfile) in lib/api.ts.
  • SIMULATED IN BROWSER STORAGE: Commits profile JSON to localStorage.setItem('waypoint_profile', ...) and redirects to /dashboard.

Step 4: User Reaches Dashboard Overview

  • File: frontend/app/dashboard/page.tsx (enclosed by AuthGuard and AppShell).
  • API Invocation: Promise.all([getStudentProfile(), getRoutes()]).
  • Execution: Resolves profile from localStorage (or mockStudent). Computes progress:
    progress = Math.round((completedSkills / totalRequiredSkills) * 100)
  • Components Rendered: JourneyCard (SVG ProgressRing), JourneyProgress (sequential milestone nodes), NextStepCard, and RouteCardPreview.

Step 5: User Inspects Skill Gaps

  • File: frontend/app/skill-gaps/page.tsx
  • API Invocation: getSkillGaps(profile.currentSkills, profile.selectedDestinationId).
  • Execution: Calculates set difference between destination requirements and student skills. Categorizes missing skills into Critical (immediate prerequisites), High Priority, and Recommended.
  • Component: SkillCard.tsx renders expandable details explaining why the skill matters and downstream dependencies.

Step 6: User Explores & Interacts with Route Map

  • Files: app/route/[id]/page.tsx → components/route-map/RouteMap.tsx
  • API Invocation: getRouteGraph(routeId, profile.selectedDestinationId, destinationTitle, profile.currentSkills).
  • Algorithm: generateDestinationGraph() computes topological depth for each skill, positions nodes vertically by layer ($y = 20 + ext{depth} imes 130$) and horizontally centered across $X=340$, connecting prerequisites via smoothstep orthogonal bezier edges.
  • Interactions:
    • Pan & Zoom canvas via mouse wheel/drag.
    • Clicking "Focus Next Skill" calls reactFlowInstance.setCenter(100, 220, { zoom: 1.2, duration: 600 }).
    • Clicking any skill node opens SkillDetailPanel.tsx drawer displaying curated study resources.

Step 7: User Discovers Opportunities

  • File: frontend/app/opportunities/page.tsx
  • API Invocation: getOpportunities(destinationId, activeType, filterMode).
  • Execution: Returns real-world contests (Smart India Hackathon, Google Summer of Code, DRDO Fellowships) matched to the student's career target. Users can filter by category pills, search by keywords, bookmark, or click "Apply Now".

WAYPOINT FRONTEND MANUAL PART 5: REACT FLOW GRAPH ENGINE

05 React Flow DAG Graph Implementation

React Flow transforms academic course prerequisites into an interactive, visual Directed Acyclic Graph (DAG). Understanding this subsystem is critical for maintaining Waypoint's core feature.

                  [ Start: Current Profile ]
                              │
               ┌──────────────┴──────────────┐
               ▼                             ▼
          [ Python ]                      [ Git ]
               │                             │
          ┌────┴─────────────┐               │
          ▼                  ▼               ▼
   [ Data Structures ] [ Linear Algebra ]  [ Cloud Basics ]
          │                  │               │
          ▼                  ▼               │
       [ SQL ]         [ Statistics ]        │
          └───────────┬──────┘               │
                      ▼                      ▼
               [ Data Analysis ]         [ MLOps ]
                      │                      │
                      ▼                      │
             [ Machine Learning ] ───────────┘
                      │
                      ▼
               [ Deep Learning ]
                      │
                      ▼
            [ Goal: AI / ML Engineer ]

1. Nodes, Edges, and Custom Types

  • Nodes (Node<RouteNodeData>): Represent skills. Contains an id, type: 'skillNode', canvas coordinates { x, y }, and a custom data payload (title, category, status, priority).
  • Edges (Edge): Represent prerequisite connections. Specifies source, target, and type: 'smoothstep'.
  • Handles (<Handle />): The anchor coordinates on the custom node where edge paths attach:
    • <Handle type="target" position={Position.Top} />: Where prerequisite edges enter.
    • <Handle type="source" position={Position.Bottom} />: Where downstream dependent edges leave.

2. Topological Layering Algorithm (generateDestinationGraph)

Located in frontend/lib/mock-data/routes.ts, this algorithm organizes an arbitrary collection of prerequisites into a clean, collision-free vertical layout:

  1. Depth Calculation: Recursively determines the longest chain of prerequisites for every skill: $$ ext{depth}(S) = 1 + \max_{P \in ext{Prerequisites}(S)} ext{depth}(P)$$ Circular dependencies are guarded using a visited Set.
  2. Vertical Slicing: Skills with the same depth are grouped into horizontal layers. Vertical coordinate is calculated as: $$Y = 20 + ext{depth} imes 130 ext{px}$$
  3. Horizontal Centering: Skills in each layer are centered symmetrically around canvas midpoint $X = 340$: $$X = 340 - rac{(N - 1) imes ext{spacing}}{2} + (i imes ext{spacing})$$
  4. Goal Anchoring: Terminal skills with no downstream dependents connect directly into the final goal node anchored at the bottom: $$Y_{ ext{goal}} = 20 + ( ext{maxDepth} + 1) imes 130 ext{px}$$

export async function getStudentProfile(): Promise<StudentProfile> {

WAYPOINT FRONTEND MANUAL PART 7: TYPESCRIPT DOMAIN TYPES

07 TypeScript Types Deep Dive

All core domain entities are declared in frontend/lib/types.ts. Using strict TypeScript contracts prevents runtime bugs by enforcing shape validity at compile time.

1. StudentProfile Entity

export type StudentStage =
  | 'just-exploring'
  | 'planning-to-enroll'
  | 'currently-enrolled'
  | 'working-professional'

export interface StudentProfile {
  name: string
  program: string
  branch: string
  studentStage: StudentStage
  semester?: number              // Optional: omitted for non-enrolled students
  cgpa?: number                  // Optional: omitted for non-enrolled students
  creditsCompleted?: number      // Optional
  currentSkills: string[]        // Array of acquired skill IDs
  selectedDestinationId: string // Matches Destination.id
}
  • Union Types (|): StudentStage restricts values to 4 exact strings. Any typo (e.g. 'enrolled') causes a compile-time error.
  • Optional Fields (?): Fields like cgpa? can be undefined, supporting beginners or graduates without crashing the UI.

2. Skill Entity & Prerequisite Graphs

export type SkillStatus = 'completed' | 'in-progress' | 'next' | 'locked'
export type SkillPriority = 'critical' | 'high' | 'recommended'

export interface Skill {
  id: string
  name: string
  category: SkillCategory
  description: string
  currentLevel: 'None' | 'Beginner' | 'Intermediate' | 'Advanced'
  requiredLevel: 'Beginner' | 'Intermediate' | 'Advanced'
  status: SkillStatus
  priority: SkillPriority
  prerequisites: string[] // Array of prerequisite skill IDs (DAG edges)
  dependents: string[]   // Array of dependent skill IDs
  estimatedWeeks: number
  whyItMatters: string
  resources?: ResourceLink[]
}

The prerequisites: string[] and dependents: string[] arrays establish graph relationships without requiring complex pointer structures.

3. Generics: ApiResponse<T>

export interface ApiResponse<T> {

  loading: boolean
}

Generics Explained: <T> acts as a type placeholder. ApiResponse<StudentProfile> ensures data is typed as a student profile, while ApiResponse<Skill[]> guarantees an array of skills, avoiding duplicate response wrapper types.

WAYPOINT FRONTEND MANUAL PARTS 12 & 13: CODE QUALITY & LEARNING ROADMAP

12 Senior Code Quality & Engineering Review

1. [CRITICAL] Insecure Client Storage of Credentials
frontend/lib/api.ts stores accounts and passwords in browser localStorage using base64 obfuscation (btoa). In production, any Cross-Site Scripting (XSS) vulnerability or malicious browser extension can read localStorage. For Review 3, authentication must be migrated to HTTP-only, secure, SameSite=Lax JWT session cookies issued by FastAPI.
2. [HIGH] Direct Mock Data Imports Inside Feature Components
components/route-map/RouteMap.tsx directly imports getDestinationById from @/lib/mock-data/destinations and getSkillById from @/lib/mock-data/skills, bypassing the API layer. When connecting FastAPI, changing lib/api.ts alone will not update these components. All data requests must go through lib/api.ts.
3. [MEDIUM] Duplicate DAG Generation Implementations
lib/mock-data/routes.ts maintains static coordinate arrays for the AI/ML route alongside a dynamic generator (generateDestinationGraph) for other routes. Unifying all routes under the procedural DAG generator will eliminate redundant coordinate maintenance.
