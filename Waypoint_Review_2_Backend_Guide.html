3. Seven Shared Rules (Must Agree on Day 1)

Inconsistent naming is the #1 cause of bugs in split frontend/backend teams. Follow these rules strictly:

  1. Skill IDs are slugs: Always use exact lowercase slugs like python, data-structures, machine-learning, cryptography. Never use arbitrary codes like SKILL_01.
  2. Skill Levels are words: None = 0, Beginner = 1, Intermediate = 2, Advanced = 3. Exactly match these string literals in CSVs and JSON responses.
  3. JSON is camelCase, Python is snake_case: In Pydantic models, always configure populate_by_name = True and alias_generator = to_camel so frontend gets currentSkills, estimatedWeeks, totalWeeks.
  4. Engines are Stateless: The skill gap and route endpoints are POST requests that receive the student's profile/skills and return calculations immediately. No database dependency inside engine logic.
  5. User is Identified by Header: X-User-Id (e.g. user_1728...). Person 3 stores one persistent profile per user ID in SQLite.
  6. Default Level Assumption: Listed skills in student onboarding default to Intermediate. The engine also accepts an optional skillLevels dictionary for granular overrides.
  7. Root Execution: Always run from repo root: uvicorn backend.main:app --reload --port 8000 and pytest.

PERSON 2 — ENGINES

5. Person 2: Deterministic Algorithmic Engines

Person 2 builds the core algorithmic intelligence that examiners will test during viva. No black-box LLMs or non-deterministic ML models are used here — all output is pure, verifiable graph theory and mathematical scheduling.

T2-1: services/skill_gap.py — The Gap Analyzer Engine

The gap calculation algorithm operates in 8 deterministic steps:

  1. Current Level Evaluation: For each required destination skill, if present in student's current_skills, assign level Intermediate (2) (or read from skill_levels map). If not present, assign None (0).
  2. Gap Value: $\text{gap} = \text{level}_{\text{required}} - \text{level}_{\text{current}}$. If $\text{gap} \le 0$, the skill is satisfied.
  3. Gap Type: If $\text{level}_{\text{current}} == \text{None} \implies \text{'full'}$; if $\text{level}_{\text{current}} > \text{None} \implies \text{'partial'}$.
  4. Prerequisite Blockers (blocks_count): Count how many other unsatisfied gap skills list this skill as a direct prerequisite.
  5. Priority Assignment:
    • If $\text{blocks\_count} \ge 2 \implies \mathbf{Critical}$ (major roadblock).
    • Else if $\text{importance} == \text{'core'} \implies \mathbf{High\ Priority}$.
    • Else $\implies \mathbf{Recommended}$.
  6. Status for DAG Map:
    • $\text{completed}$: student already has the skill.
    • $\text{next}$: student needs the skill, and all its prerequisites are completed.
    • $\text{locked}$: student needs the skill, but one or more prerequisites are still missing.
  7. Sorting: Sort gaps primarily by Priority ($\text{Critical} \to \text{High} \to \text{Recommended}$), secondarily by gap magnitude, and tertiarily by title.
  8. Audit Explanation: Fill a deterministic sentence template with real numbers (e.g. "Required Advanced, currently at None (gap 3). Blocks 2 downstream skills you need.").

T2-2: services/route_builder.py — Multi-Track Timeline Scheduler

A route is an ordered weekly roadmap. The engine builds three distinctive variants:

Route ID Route Name Workload Concurrent Slots Pace Factor Skills Included
fast-track Fast Track High 3 skills at once 0.7× duration Critical + High priority gaps only.
balanced Balanced Route Medium 2 skills at once 1.0× duration Critical + High + Supporting skills (isRecommended: true).
foundation-first Foundation First Low 2 skills at once 1.3× duration All gap skills (includes Optional + foundational deep-dives).

Scheduling Algorithm:

  • $\text{weeks} = \max(1, \text{round}(\text{estimated\_weeks} \times \text{pace\_factor}))$.
  • A skill is eligible to begin in week $W$ only after all its prerequisite skills have completed ($\text{weekEnd} < W$).
  • Available study slots are prioritized by Priority ($\text{Critical}$ first, then larger gaps).
  • totalWeeks is the maximum weekEnd across all steps; skillCount is the total skills in the route.

T2-3: Topological React Flow DAG Generator

Generates the node and edge structures required by the frontend's React Flow canvas:

  • Nodes: Exactly one start node at $(340, 20)$, completed prerequisites, active gap skills, and one final goal node.
  • Topological Layering: Compute the longest prerequisite path from start to each node: $$\text{layer}(S) = \max_{\text{prereqs } P}(\text{layer}(P)) + 1$$ $$\text{coordinate } y = 20 + \text{layer} \times 110$$
  • Horizontal Spacing: In each layer, distribute $N$ nodes symmetrically centered around $x = 340$, spaced $180\text{px}$ apart.
  • Edges: Connect prerequisite_id $\to$ skill_id with type: 'smoothstep'. Connect start to skills with no prerequisites; connect terminal skills to goal. Set animated: true for edges leading into next skills.

9. Viva Cheat Sheet — Say It in Plain Words

Examiner Question Recommended Engineering Answer
"Why not use an LLM (like GPT-4) to generate routes?" LLMs hallucinate prerequisite orders, are non-deterministic, cost per token, and take 3–5 seconds per call. Our topological scheduler is deterministic, instantaneous (<10ms), 100% mathematically verifiable, and works offline without API costs.
"How do you determine which skills are Critical vs High Priority?" We calculate a blocks_count: how many other missing skills have this skill as a direct dependency. If a skill blocks 2 or more downstream skills, it is mathematically Critical because it bottlenecks the entire journey.
"How does the route scheduler assign weeks?" It uses a constrained bin-packing model: a skill can only start in week $W$ if all its prerequisites finished in week $\le W-1$, and subject to maximum concurrent study slots (2 for Balanced, 3 for Fast Track).
"How is data scalability handled when adding new careers?" The engine is entirely data-driven. To add a new career track (e.g. Cloud Architect), we simply add rows to destinations.csv and destination_requirements.csv. Zero lines of Python code need to be rewritten.
"How do you ensure authenticity of opportunities?" Every entry in data/opportunities.csv links directly to official government bodies (AICTE, Ministry of Defence iDEX, MoE PMRF) or global programs (Google Summer of Code, Y Combinator, DAAD) with verified URLs.
