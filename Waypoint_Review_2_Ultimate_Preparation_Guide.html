2. End-to-End Lifecycle of a Student Query

Query: "I am a first-year IT student interested in AI/ML. What opportunities should I apply for?"

  1. Client Capture: AIOpportunitySearch.tsx collects the search text and student profile (Semester: 1, Branch: IT, Skills: Python).
  2. API Dispatch: opportunity-provider.ts issues POST request to /api/opportunities/search.
  3. Schema Parsing: FastAPI receives payload into OpportunitySearchRequest Pydantic model.
  4. LLM Intent Parsing: parse_intent_with_gemini() sends prompt to Gemini Flash with response schema OpportunityAIIntent. Extracted JSON: { target_year: 1, domains: ["AI", "ML"], types: ["internship", "research"] }.
  5. Catalog Retrieval: filter_opportunities() pulls all programs from data/opportunities.csv that match 1st-year IT criteria.
  6. Deterministic 100-Point Scoring: opportunity_ranker.py evaluates each candidate against the student's profile across 8 weighted metrics.
  7. Grounded Explanation: generate_grounded_explanations_with_gemini() receives top candidates and generates factual justifications without inventing opportunities.
  8. Client Rendering: OpportunitiesList.tsx displays ranked cards with verified application links, match scores, and trust badges.

⚙️ Section 4: Core Algorithms Explained from Scratch

1. Kahn's Algorithm for DAG Route Generation (`route_builder.py`)

A Directed Acyclic Graph (DAG) represents skills where edges point from prerequisites to advanced topics. Kahn's algorithm performs a topological sort to layer skills so that a student never encounters a topic before its prerequisites.

def build_route_dag(destination_id: str, acquired_skills: List[str]):
    # 1. Compute in-degree for every skill node
    in_degree = {skill: 0 for skill in all_skills}
    for u in adj_list:
        for v in adj_list[u]:
            in_degree[v] += 1
            
    # 2. Collect all nodes with 0 in-degree (no prerequisites)
    queue = deque([s for s in all_skills if in_degree[s] == 0])
    layers = []
    
    # 3. Process node level-by-level
    while queue:
        current_layer = []
        for _ in range(len(queue)):
            node = queue.popleft()
            current_layer.append(node)
            for neighbor in adj_list[node]:
                in_degree[neighbor] -= 1
                if in_degree[neighbor] == 0:
                    queue.append(neighbor)
        layers.append(current_layer)
    return layers

2. The Deterministic 100-Point Opportunity Ranking Model

Every candidate opportunity is evaluated against an 8-factor mathematical model:

Factor Weight Calculation Logic
Profile / Branch Match 25 Points Full points if student's branch (e.g. IT) matches opportunity eligibility; 15 if open to all STEM; 0 if non-eligible.
Career Alignment 20 Points Semantic category overlap between student destination (e.g. AI/ML Engineer) and opportunity domain.
Academic Eligibility 15 Points Verifies student semester ≤ max semester and CGPA ≥ minimum required CGPA.
Current Skill Match 10 Points Percentage of opportunity required skills already possessed by the student.
Skill Gap Alignment 10 Points Crucial Metric: Rewards opportunities that teach skills currently identified as student gaps.
Freshness 10 Points Days since opportunity verification: 10 if <7 days, 7 if <30 days, 4 if <90 days.
Deadline Urgency 5 Points 5 if closing within 14 days, 3 if within 30 days, 1 if later.
Source Trust 5 Points 5 for government portals (ISRO, SIH, GSoC), 4 for enterprise official domains, 2 for third-party aggregators.
TOTAL SCORE 100 Points Deterministic, transparent score out of 100 presented on opportunity cards.

🎓 Section 5: 40 Likely Viva Questions & Answers

Category A: Core System & Architecture

Basic 1. What problem does Waypoint solve?
Traditional job boards display thousands of senior-level listings irrelevant to junior students, while static syllabi fail to show dependency roadmaps. Waypoint acts as an academic GPS by generating prerequisite-respecting DAG learning routes and discovering verified opportunities tailored to the student's exact semester and skills.
Basic 2. Why did you use FastAPI over Flask or Django?
FastAPI natively supports asynchronous concurrency (async/await) essential for non-blocking external LLM API calls, provides automatic Pydantic request validation, and generates interactive Swagger documentation out of the box with superior performance.
Architecture 3. Why are completed tasks editable on your route map?
Real-world academic learning is non-linear. Students often need to reopen completed tasks to review forgotten topics, update personal notes, or modify target dates. Locking completed tasks creates an inflexible and unrealistic user experience.
Architecture 4. How does edge bridging work when a task is deleted?
In RouteMap.tsx, when a task node is removed, we identify all incoming source nodes and outgoing target nodes. We programmatically create direct edges from each incoming node to each outgoing node, preventing the downstream graph from becoming detached or orphaned.
Architecture 5. What is the difference between Edit Route and Regenerate Route?
Edit Route enables the student to customize individual tasks, reorder nodes, and update notes while preserving user changes. Regenerate Route resets the entire graph back to the default AI recommendation; to prevent data loss, a warning modal (RegenerateConfirmModal.tsx) requires confirmation before overwriting customizations.

Category B: AI, LLM & Personalization

AI 6. How do you prevent the LLM from hallucinating fake opportunities or application deadlines?
We enforce strict architectural boundaries: the LLM is never permitted to generate opportunity records. Opportunities are strictly retrieved from our verified catalog. The LLM only parses natural language search intent into structured JSON criteria and writes grounded explanations for candidate records.
AI 7. What happens if the Gemini API key is missing or the external API times out?
gemini_service.py implements a seamless fallback mechanism. If Gemini fails, the application falls back to our deterministic rule-based keyword intent parser in opportunity_search.py. The application continues running without errors.
AI 8. Why didn't you use vector embeddings for opportunity matching?
Vector embeddings measure semantic text similarity, not strict logical eligibility. In academic matching, a 1st-year student querying "machine learning" could semantically match an advanced PhD research fellowship because of high cosine similarity. Structured faceted filtering combined with our 100-point deterministic model ensures strict eligibility compliance.
AI 9. What is Grounded Generation in your explanation engine?
Grounded generation means the prompt restricts the LLM to only synthesize statements based on the concrete opportunity attributes (title, organization, eligibility) provided in the context prompt, preventing outside unverified claims.

Category C: Algorithms & Graph Theory

Algorithms 10. Which algorithm powers your route generation?
Kahn's topological sorting algorithm implemented in backend/services/route_builder.py. It calculates the in-degree of every skill node and builds sequential learning tiers starting from zero in-degree nodes.
Algorithms 11. How do you detect cycles in your prerequisite graph?
During Kahn's algorithm, if the total count of visited nodes is less than the total number of nodes in the graph, at least one cycle exists (e.g. A requires B, and B requires A). Our service detects this and flags an invalid dependency error.
Algorithms 12. How does the skill gap engine determine if a skill is 'next' vs 'locked'?
In backend/services/skill_gap.py, for every missing skill, we check if all of its direct prerequisites are present in the student's acquired skills list. If all prerequisites are met, status is next; if one or more are missing, status is locked.
